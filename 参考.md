要改成**真正的 chunk0 / chunk1 双回传并行**，需要同时改 `ggml-backend-meta.cpp` 和 `ggml-rpc.cpp`。前面我说“两个 outstanding task”还不够完整：你现在 `transfer_worker` 本质上只有一个 `std::thread`，任务 FIFO 执行，所以两个 return 即使都 enqueue，也还是串行。

而 RPC 端也只有一个共享的 `"_transfer"` socket；所有 snapshot get 最终都走这一条连接。

所以我建议做成下面这个结构：

```text
chunk0 compute ─→ snapshot slot0 ─→ worker0 ─→ snapshot_socket0 ─→ PC tmp0 ┐
                                                                             ├→ join → next layer
chunk1 compute ─→ snapshot slot1 ─→ worker1 ─→ snapshot_socket1 ─→ PC tmp1 ┘
```

而且**先只对 prefill + snapshot 路径启用**，decode 先不动。

## 二、必须给两个 return 分开 tmp buffer

这个非常重要。

你当前 prefill reduce 是：

```cpp
ggml_tensor * node_tmp = get_node_aux(node_dst);
set_tmp_data(node_tmp, j_dst, 0);
```

也就是说无论 chunk0 还是 chunk1，都使用：

```text
bcj_dst.bufs[0]
```



如果我们直接让两个 worker 并发：

```text
worker0 -> tmp buffer 0
worker1 -> tmp buffer 0
```

一定有覆盖风险。

所以在 `backend_config` 里面增加两个独立的 prefill scratch：

```cpp
struct backend_config {
    ggml_backend_t backend;

    std::vector<cgraph_config>           cgraphs;
    std::vector<ggml_tensor *>           nodes;
    std::vector<ggml_backend_buffer_ptr> bufs;

    std::array<
        ggml_backend_buffer_ptr,
        PREFILL_RETURN_LANES
    > prefill_reduce_bufs;

    backend_config(
        ggml_backend_t backend,
        const size_t n_reduce_steps)
        : backend(backend) {
        bufs.resize(n_reduce_steps);
    }
};
```

你现在 `set_tmp_data()` 下面再加：

```cpp
auto set_prefill_tmp_data =
    [&](ggml_tensor * tensor,
        const size_t j,
        const size_t lane) {

        GGML_ASSERT(lane < PREFILL_RETURN_LANES);

        auto & bcj = backend_ctx->backend_configs[j];
        auto & buf_ptr = bcj.prefill_reduce_bufs[lane];

        if (!buf_ptr ||
            ggml_backend_buffer_get_size(buf_ptr.get()) <
                backend_ctx->max_tmp_size) {

            buf_ptr.reset(
                ggml_backend_alloc_buffer(
                    bcj.backend,
                    backend_ctx->max_tmp_size));
        }

        tensor->buffer = buf_ptr.get();
        tensor->data =
            ggml_backend_buffer_get_base(buf_ptr.get());
    };
```

你现有 `get_node_aux()` / `get_cgraph_aux()` 每次本身就在递增索引取不同对象，所以 **tensor 描述符和 aux graph 已经是分开的**；真正缺的是 tmp data buffer。

## 三、把单个 pending task 改成两个 lane

现在是：

```cpp
uint64_t pending_prefill_reduce_task = 0;
int pending_prefill_reduce_layer = -1;
```



改成：

```cpp
std::array<uint64_t, PREFILL_RETURN_LANES>
    pending_prefill_reduce_task { 0, 0 };

std::array<int, PREFILL_RETURN_LANES>
    pending_prefill_reduce_layer { -1, -1 };

std::array<
    ggml_backend_meta_transfer_worker *,
    PREFILL_RETURN_LANES
> pending_prefill_reduce_worker { nullptr, nullptr };
```

然后加几个 helper：

```cpp
auto has_pending_prefill_reduce = [&]() {
    for (size_t lane = 0;
         lane < PREFILL_RETURN_LANES;
         ++lane) {

        if (pending_prefill_reduce_task[lane] != 0) {
            return true;
        }
    }

    return false;
};

auto has_pending_prefill_reduce_for_layer =
    [&](int layer) {

        for (size_t lane = 0;
             lane < PREFILL_RETURN_LANES;
             ++lane) {

            if (pending_prefill_reduce_task[lane] != 0 &&
                pending_prefill_reduce_layer[lane] == layer) {
                return true;
            }
        }

        return false;
    };

auto wait_prefill_reduce_lane =
    [&](size_t lane) -> ggml_status {

        if (pending_prefill_reduce_task[lane] == 0) {
            return GGML_STATUS_SUCCESS;
        }

        GGML_ASSERT(
            pending_prefill_reduce_worker[lane] != nullptr);

        const ggml_status status =
            pending_prefill_reduce_worker[lane]->wait(
                pending_prefill_reduce_task[lane]);

        pending_prefill_reduce_task[lane] = 0;
        pending_prefill_reduce_layer[lane] = -1;
        pending_prefill_reduce_worker[lane] = nullptr;

        return status;
    };

auto wait_all_prefill_reduces =
    [&]() -> ggml_status {

        ggml_status result = GGML_STATUS_SUCCESS;

        for (size_t lane = 0;
             lane < PREFILL_RETURN_LANES;
             ++lane) {

            const ggml_status status =
                wait_prefill_reduce_lane(lane);

            if (result == GGML_STATUS_SUCCESS &&
                status != GGML_STATUS_SUCCESS) {
                result = status;
            }
        }

        return result;
    };
```

# 手机 RPC server 不需要改协议

你 server 本来就有：

```cpp
std::array<rpc_snapshot_slot, 2> slots;
```

也就是 slot0 / slot1 本来就是两个独立状态和 mutex。

而且 `send_snapshot()` 在真正 `sock->send_data()` 前已经释放了 slot mutex，所以 slot0 和 slot1 可以各自在不同 socket 上发送。 

更重要的是你的 RPC server 对**每个 client connection 单独起线程**：

```cpp
std::thread([shared_server, client_socket, n_devices]() {
    rpc_serve_client(...);
}).detach();
```



所以两条 snapshot socket 在服务端也确实能并发处理。
