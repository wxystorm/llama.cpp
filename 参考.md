可以。我们现在进入 **Phase 4C：把 BEST PLAN 真正变成运行时配置**。

不过这一层最好不要真的把：

```text
LLAMA_HYBRID_PC_PCT
LLAMA_HYBRID_PHONE_LAYERS
LLAMA_HYBRID_GPU_PC_LAYERS
LLAMA_PREFILL_CHUNKS
```

写进系统环境变量。更稳的是：

```text
Profiler
   ↓
4A + 4B
   ↓
BEST PLAN
   ↓
runtime plan override
   ↓
llama-model.cpp / qwen3.cpp 直接读取
   ↓
load_tensors()
```

环境变量只保留作手动 fallback。

你现在 `llama-model.cpp` 的层策略仍然直接读 `PC_PCT / PHONE_LAYERS / GPU_PC_LAYERS`。 而 Qwen3 的 Prefill K 仍然直接读 `LLAMA_PREFILL_CHUNKS`。

这轮先把这条“BEST PLAN → runtime”的桥打通。

## 2. `llama-hybrid.cpp`：保存 BEST PLAN

顶部增加：

```cpp
#include <cstdlib>
#include <optional>
```

然后在常量区下面：

```cpp
static std::mutex g_llama_hybrid_runtime_plan_mutex;
static std::optional<llama_hybrid_plan>
    g_llama_hybrid_runtime_plan;
```

加入：

```cpp
static bool llama_hybrid_runtime_plan_valid(
        const llama_hybrid_plan & plan) {

    if (plan.tensor_layers < 0 ||
        plan.phone_layers < 0 ||
        plan.pc_layers < 0) {
        return false;
    }

    if (plan.tensor_layers +
            plan.phone_layers +
            plan.pc_layers <= 0) {
        return false;
    }

    if (plan.tensor_pc_ratio <= 0.0f ||
        plan.tensor_pc_ratio >= 1.0f) {
        return false;
    }

    if (plan.gpu_pc_layers < 0 ||
        plan.gpu_pc_layers >
            plan.pc_layers) {
        return false;
    }

    if (plan.tensor_chunks_per_ubatch != 1 &&
        plan.tensor_chunks_per_ubatch != 2 &&
        plan.tensor_chunks_per_ubatch != 4) {
        return false;
    }

    return true;
}
```

然后处理 dual-return。因为现在 Meta 里面还是通过环境变量判断：

```cpp
std::getenv("GGML_META_PREFILL_DUAL_RETURN")
```

来决定双 return lane。

所以暂时只对这个内部 GGML 开关自动设置：

```cpp
static void llama_hybrid_runtime_set_dual_return(
        bool enabled) {

#ifdef _WIN32

    _putenv_s(
        "GGML_META_PREFILL_DUAL_RETURN",
        enabled ? "1" : "");

#else

    if (enabled) {
        setenv(
            "GGML_META_PREFILL_DUAL_RETURN",
            "1",
            1);
    } else {
        unsetenv(
            "GGML_META_PREFILL_DUAL_RETURN");
    }

#endif
}
```

然后实现 API：

```cpp
bool llama_hybrid_runtime_plan_set(
        const llama_hybrid_plan & plan) {

    if (!llama_hybrid_runtime_plan_valid(plan)) {

        LLAMA_LOG_ERROR(
            "[HYBRID_RUNTIME_PLAN] "
            "refusing invalid plan\n");

        return false;
    }

    {
        std::lock_guard<std::mutex> lock(
            g_llama_hybrid_runtime_plan_mutex);

        g_llama_hybrid_runtime_plan =
            plan;
    }

    const bool dual_return =
        plan.tensor_layers > 0 &&
        plan.tensor_chunks_per_ubatch > 1;

    llama_hybrid_runtime_set_dual_return(
        dual_return);

    LLAMA_LOG_INFO(
        "[HYBRID_RUNTIME_PLAN_SET] "
        "T=%d P=%d C=%d "
        "R=%.3f G=%d K=%d "
        "dual_return=%d "
        "predicted_ms=%.3f\n",
        plan.tensor_layers,
        plan.phone_layers,
        plan.pc_layers,
        plan.tensor_pc_ratio,
        plan.gpu_pc_layers,
        plan.tensor_chunks_per_ubatch,
        dual_return ? 1 : 0,
        plan.predicted_ms);

    return true;
}

bool llama_hybrid_runtime_plan_get(
        llama_hybrid_plan & plan) {

    std::lock_guard<std::mutex> lock(
        g_llama_hybrid_runtime_plan_mutex);

    if (!g_llama_hybrid_runtime_plan) {
        return false;
    }

    plan =
        *g_llama_hybrid_runtime_plan;

    return true;
}

void llama_hybrid_runtime_plan_clear() {

    {
        std::lock_guard<std::mutex> lock(
            g_llama_hybrid_runtime_plan_mutex);

        g_llama_hybrid_runtime_plan.reset();
    }

    llama_hybrid_runtime_set_dual_return(
        false);
}
```

    applied_plan.tensor_chunks_per_ubatch);

# 4. `llama-model.cpp`：层布局优先使用自动 plan

这是最关键的一步。

现在这里：

```cpp
const int n_layer = hparams.n_layer();
const double pc_pct = llama_hybrid_pc_pct();

const int pc_layers = ...
const int phone_layers = ...

const std::string pc_layout = ...
```



替换成：

```cpp
const int n_layer =
    hparams.n_layer();

llama_hybrid_plan runtime_plan;

const bool has_runtime_plan =
    llama_hybrid_runtime_plan_get(
        runtime_plan);

int pc_layers;
int phone_layers;
int gpu_pc_layers;
double pc_pct;
std::string pc_layout;

if (has_runtime_plan) {

    if (runtime_plan.tensor_layers +
            runtime_plan.phone_layers +
            runtime_plan.pc_layers !=
        n_layer) {

        throw std::runtime_error(
            format(
                "hybrid runtime plan layer mismatch: "
                "plan=%d+%d+%d model=%d",
                runtime_plan.tensor_layers,
                runtime_plan.phone_layers,
                runtime_plan.pc_layers,
                n_layer));
    }

    pc_layers =
        runtime_plan.pc_layers;

    phone_layers =
        runtime_plan.phone_layers;

    gpu_pc_layers =
        runtime_plan.gpu_pc_layers;

    pc_pct =
        100.0 *
        (double) pc_layers /
        (double) n_layer;

    //
    // Planner topology 永远是：
    //
    // TS -> PHONE -> PC
    //
    pc_layout =
        "tail";

} else {

    pc_pct =
        llama_hybrid_pc_pct();

    pc_layers =
        std::clamp(
            (int) std::llround(
                n_layer *
                pc_pct /
                100.0),
            0,
            n_layer);

    phone_layers =
        std::clamp(
            llama_hybrid_phone_layers(),
            0,
            n_layer -
                pc_layers);

    gpu_pc_layers =
        llama_hybrid_gpu_pc_layers();

    pc_layout =
        phone_layers > 0
            ? "tail"
            : llama_hybrid_pc_layout();
}
```

然后原来的：

```cpp
const int n_gpu_pc =
    std::min<int>(
        llama_hybrid_gpu_pc_layers(),
        pc_layer_ids.size());
```

改为：

```cpp
const int n_gpu_pc =
    std::min<int>(
        gpu_pc_layers,
        pc_layer_ids.size());
```

这样：

```text
G=13
```

就不再需要：

```powershell
$env:LLAMA_HYBRID_GPU_PC_LAYERS="13"
```

# 5. 自动覆盖 `R`

这个不能漏。

Meta 的真正 tensor shard 是通过：

```cpp
const float * tensor_split =
    ud->model->tensor_split();
```

决定每个设备分多少。

所以在上面 `has_runtime_plan` 分支里，再加入：

```cpp
if (llama_max_devices() < 2) {
    throw std::runtime_error(
        "hybrid runtime plan requires "
        "at least two tensor split slots");
}

pimpl->tensor_split_owned.assign(
    llama_max_devices(),
    0.0f);

pimpl->tensor_split_owned[0] =
    runtime_plan.tensor_pc_ratio;

pimpl->tensor_split_owned[1] =
    1.0f -
    runtime_plan.tensor_pc_ratio;

params.tensor_split =
    pimpl->tensor_split_owned.data();

LLAMA_LOG_INFO(
    "[HYBRID_RUNTIME_SPLIT] "
    "pc=%.3f phone=%.3f\n",
    pimpl->tensor_split_owned[0],
    pimpl->tensor_split_owned[1]);
```

这很重要，因为 constructor 本来就会把命令行的 `tensor_split` 保存到自己的 owned vector。

现在我们是在真正加载 tensor **之前**重新覆盖它。

所以 USB：

```text
R=.75
```

自动变成：

```text
tensor_split = [0.75, 0.25]
```

效果等价于：

```text
--tensor-split 3,1
```

LAN 的 `T=0`：

```text
R=.50
```

虽然实际上没有 TS layer，但保持：

```text
[0.5, 0.5]
```

即可。

# 7. Qwen3：自动使用 planner 的 K

当前函数是：

```cpp
static int qwen3_prefill_ffn_chunk_count() {
    const char * value =
        std::getenv("LLAMA_PREFILL_CHUNKS");

    return value == nullptr
        ? 0
        : std::max(1, std::atoi(value));
}
```



改成：

```cpp
static int qwen3_prefill_ffn_chunk_count() {

    llama_hybrid_plan plan;

    if (llama_hybrid_runtime_plan_get(
            plan)) {

        //
        // T=0 时 K 无意义。
        //
        if (plan.tensor_layers == 0) {
            return 1;
        }

        return std::max(
            1,
            plan.tensor_chunks_per_ubatch);
    }

    const char * value =
        std::getenv(
            "LLAMA_PREFILL_CHUNKS");

    return value == nullptr
        ? 0
        : std::max(
            1,
            std::atoi(value));
}
```

Qwen2 也做完全一样的修改，因为它现在也是直接读这个环境变量。

Llama 那份 `llama_prefill_ffn_chunk_count()` 也同样改。

`LLAMA_CHUNKS` 暂时**不要动**，因为 planner 目前选的是 Prefill K，不是 Decode K。

## 这样六个参数已经全部映射了

| Planner | 自动作用                  |
| ------- | --------------------- |
| `T`     | `hybrid_layer_modes`  |
| `P`     | `hybrid_layer_modes`  |
| `C`     | `hybrid_layer_modes`  |
| `R`     | `params.tensor_split` |
| `G`     | `pc_layer_backends`   |
| `K`     | Prefill chunk builder |

所以 USB 的：

```text
T24 P26 C14 R.75 G13 K2
```

以后实际加载就应该打印：

```text
[HYBRID_RUNTIME_PLAN_SET]
T=24 P=26 C=14 R=0.750 G=13 K=2 dual_return=1

[HYBRID_RUNTIME_SPLIT]
pc=0.750 phone=0.250

[HYBRID_SPLIT]
source=planner
tensor_split=24
phone_only=26
pc_only=14
gpu_pc=13
R=0.750
```

此时你原来手动设置的：

```text
LLAMA_HYBRID_PC_PCT
LLAMA_HYBRID_PHONE_LAYERS
LLAMA_HYBRID_GPU_PC_LAYERS
LLAMA_PREFILL_CHUNKS
```

都会变成 **fallback**，planner 存在时不再生效。

所以这一步做完以后：

```text

```

```text
llama-cli
  ↓
打开 GGUF metadata
  ↓
直接调用 profiler
  ↓
4A / 4B
  ↓
llama_hybrid_runtime_plan_set(BEST)
  ↓
llama_model_create()
  ↓
load_hparams()
  ↓

```

也就是我们最开始定的目标。
