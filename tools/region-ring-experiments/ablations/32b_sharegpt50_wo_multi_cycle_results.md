# 32B ShareGPT50 Runtime 消融：w/o Multi-Cycle（G–P–G）

- 模型：Qwen3-32B-Q4_K_M；ShareGPT50 五组（0 / 128 / 256 / 512 / 1024），每组 10 条，共 50 条、27,417 tokens
- Full Cycle：`G7,P4,G7,P4,G8,P5,G7,P4,G7,P4,G7`
- 本消融：逻辑 `G36,P21,G7`；实际 GPU 权重窗口 `G7,G7,G8,G7,G7,P21,G7`，固定 43 GPU 层、21 Phone 层
- 消融机制：去掉多轮 GPU–Phone 交替，只保留一次 GPU→Phone→GPU；GPU 双 Bank、后台异步预取、Drain-First、资源感知调度和 Phone HTP 保持开启
- Planner：**每条 Prompt 动态搜索并应用 XC/XG/XP**（`source=LOCKED_CHUNK_ONLY`），不重放 Full Cycle 的 Chunk；固定层分配，Chunk 随 Prompt 变化
- Full Cycle 基线：`32b-server-chunk256-all50-new/summary.csv`
- 消融结果目录：`32b-ablation-wo-multi-cycle-native-chunk-all50/`；数据来源：用户提供的 50 条 `llama-server` 控制台 Prefill/Planner 记录（`prompt_1024_10` 为第一条锚点）

| 0 | 10 | 911 | 50.245 | 41.365 | 17.67% | 1.215× |
| 128 | 10 | 2,040 | 88.413 | 68.880 | 22.09% | 1.284× |
| 256 | 10 | 3,283 | 110.446 | 93.724 | 15.14% | 1.178× |
| 512 | 10 | 8,032 | 135.603 | 121.824 | 10.16% | 1.113× |
| 1024 | 10 | 13,151 | 141.907 | 123.917 | 12.68% | 1.145× |
| **全部** | **50** | **27,417** | **123.037** | **105.969** | **13.87%** | **1.161×** |

## 4. G–P–G 原生动态 Chunk 选择

| Token 组 | XC | 选定 XG | 选定 XP | 常见选定组合 |
|---|---:|---|---|---|
| 0 | 16 | 24 / 32 / 48 | 48 / 64 / 96 | XG24/XP48、XG32/XP64、XG48/XP64（各 3 条） |
| 128 | 16 | 64 / 80 / 96 | 96 / 112 / 128 / 160 / 192 | XG64/XP96（3 条） |
| 256 | 32 | 96 / 112 / 128 / 160 | 128 / 160 / 192 | XG96/XP192、XG112/XP192、XG128/XP128（各 3 条） |
| 512 | 32 | 160 / 256 | 160 / 256 | XG256/XP256（9/10 条） |
| 1024 | 32 | 192 / 256 | 192 / 256 | XG256/XP256（7/10 条） |

- 50 条请求共产生 **15 种**不同的 XG/XP 组合，其中 XG256/XP256 为 **16 条**。
- 原始 Runtime 的 tiny-tail 合并可能使实际 Chunk 大于计划值：`prompt_1024_10` 计划 XG/XP=256、实际为 265；`prompt_1024_03` 计划 256、实际为 272；`prompt_0_04` 计划 XP=64、实际为 75。上述均为日志记录的运行宽度，不是 Planner 搜索越界。

**消融结论：** 取消 Multi-Cycle 且保留动态 Chunk、双 GPU Bank、异步预取及 Drain-First 后，32B ShareGPT50 的加权 Prefill 吞吐由 **123.037** 降至 **105.969 tok/s**（下降 **13.87%**），总 Prefill 耗时由 **222834.820** 增至 **258726.680 ms**（增加 **16.11%**）；Full Cycle 相对单趟 G–P–G 提速 **1.161×**。
