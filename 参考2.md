很好，这说明 **graph 侧已经定住了**。恢复 per-chunk dependency 后，Meta 的分图逻辑会在 `PARTIAL` 节点处切 subgraph，所以 `chunk0 downstream` 会自然落到 `down_chunk0` 和 `down_chunk1` 两个归约边界之间。

而你现在 Meta 的调度已经能做到第一部分 Pipeline C：

```text
Phone Wdown0
   ↓ snapshot0 / TX0
Phone Wdown1 ────────────────┐
                             │ overlap
                       PC downstream0
                       PC local Wdown1
```

因为 snapshot0 arm 后你已经立即 `start(j_src, i+1)`；等 chunk0 transfer+ADD 完才启动 PC 的 `i+1`。

但现在还有一个很明确的串行点，下一阶段应该直接解决它。

### 当前还浪费了一段：chunk1 的传输启动太晚

现在 sg1 大致是：

```text
ARM0
start Phone sg2

TX0 + ADD0
↓
start PC sg2
↓
wait Phone
wait PC sg2
↓
返回

进入 sg2
↓
ARM1
GET snapshot1
TX1 + ADD1
```

代码确实会在启动 PC `i+1` 后等 Phone 和 PC 都结束，返回外层后才处理下一个 subgraph 的 communication。 外层又是一个 subgraph 一个 subgraph 地进入 `specialized_communication()`。

所以现在其实还没有做到：

```text
PC downstream0 + PC Wdown1
||
Phone snapshot1 + Phone→PC TX1
```

而这正是下一块大收益。

---

## 下一 commit：提前预取 chunk1 snapshot 到 PC 的 host 内存

这里有个很重要的设计点：

**不要提前把 chunk1 直接 copy 到 PC backend 的 `node_tmp`。**

因为此时 PC 正在执行 sg2。我们要让网络接收和 PC graph 完全互不干扰。

改成：

```text
Phone snapshot1
↓
网络
↓
PC host staging buffer     ← 只到普通内存

                     ||
                     PC sg2:
                     downstream0
                     local Wdown1

两边都完成
↓
host staging -> PC node_tmp1
↓
ADD1
```

这样才是真正完整的 Pipeline C。

---

你可以在 `ggml_backend_meta_graph_compute()` 里先加一个本次 graph 调用局部的 pending state，例如：

```cpp
struct prefetched_snapshot {
    bool valid = false;

    size_t subgraph = SIZE_MAX;

    uint64_t seq  = 0;
    uint32_t slot = 0;

    uint64_t task_id = 0;

    ggml_tensor * node_src = nullptr;

    std::vector<uint8_t> data;
};

prefetched_snapshot prefetched;
```

现在先只允许 **one-lookahead** 就够了，因为默认就是 2 chunks。

---

### 在处理 chunk0 时提前 ARM chunk1

你当前这里：

```cpp
snapshot_arm(... chunk0 ...);

compute_workers->start(j_src, i + 1);

const ggml_status transfer_status =
    transfer_worker->wait(task_id);

if (transfer_status == GGML_STATUS_SUCCESS) {
    compute_workers->start(j_dst, i + 1);
}
```

中间插一段。

先：

```cpp
compute_workers->start(j_src, i + 1);
```

然后马上：

```cpp
const ggml_status phone_submit_status =
    compute_workers->wait(j_src);

if (phone_submit_status != GGML_STATUS_SUCCESS) {
    return phone_submit_status;
}
```

这里要理解清楚：

对于现在 RPC 的 `graph_compute_async`，这个 wait 主要是在等 **GRAPH1 命令已经通过 compute socket 发出去**，不是等 Phone 真正把 graph1 算完。

我们需要这个 wait，只为了确保 socket 顺序一定是：

```text
ARM0
GRAPH1
ARM1
```

而绝不能：

```text
ARM0
ARM1
GRAPH1
```

---

接下来拿出 `i+1` Phone graph 的最后一个节点：

```cpp
auto & bc_next_src =
    backend_ctx->backend_configs[j_src];

ggml_cgraph * next_graph =
    bc_next_src.cgraphs[i + 1].cgraph_main;

ggml_tensor * next_node_src =
    next_graph->nodes[next_graph->n_nodes - 1];
```

既然你已经判断：

```cpp
next_is_ffn_down_chunk
```

那么这里就是：

```text
ffn_down_chunk_1
```

分一个新的 seq：

```cpp
const uint64_t next_seq =
    backend_ctx->next_snapshot_seq++;

const uint32_t next_slot =
    next_seq & 1;
```

然后：

```cpp
const bool armed_next =
    snapshot_arm(
        bc_next_src.backend,
        next_node_src,
        0,
        ggml_nbytes(next_node_src),
        next_slot,
        next_seq);

GGML_ASSERT(armed_next);
```

Phone compute socket 就变成：

```text
SNAPSHOT0
GRAPH1
SNAPSHOT1
```

完全本地串行、安全。

## 然后把 GET1 提前排到 transfer worker

这里不要：

```cpp
ggml_backend_tensor_copy_async(
    phone,
    pc,
    next_node_src,
    node_tmp);
```

而是：

```cpp
prefetched.valid    = true;
prefetched.subgraph = i + 1;
prefetched.seq      = next_seq;
prefetched.slot     = next_slot;
prefetched.node_src = next_node_src;

prefetched.data.resize(
    ggml_nbytes(next_node_src));
```

然后 enqueue：

```cpp
prefetched.task_id =
    backend_ctx->transfer_worker->enqueue(
        [&, next_node_src,
            next_slot,
            next_seq](uint64_t) -> ggml_status {

            set_snapshot_read(
                true,
                next_slot,
                next_seq);

            const int64_t t0 =
                ggml_time_us();

            ggml_backend_tensor_get(
                next_node_src,
                prefetched.data.data(),
                0,
                prefetched.data.size());

            const int64_t us =
                ggml_time_us() - t0;

            set_snapshot_read(
                false,
                0,
                0);

            if (pipeline_debug) {
                printf(
                    "[META_PREFETCH_NET] "
                    "sg=%zu seq=%" PRIu64
                    " slot=%u bytes=%zu "
                    "time=%.3f ms\n",
                    i + 1,
                    next_seq,
                    next_slot,
                    prefetched.data.size(),
                    us / 1000.0);
            }

            return GGML_STATUS_SUCCESS;
        });
```

注意这个 task 会排在当前 `task0` 后面，因为 transfer worker 本来就是 FIFO queue。

于是自动形成：

```text
transfer worker:

TX0 + ADD0
↓
GET snapshot1 -> HOST
```

而主线程：

```text
wait task0
↓
start PC sg2
```

所以：

```text
                        ┌── GET snapshot1 → host
task0 done ─────────────┤
                        └── PC sg2
                            downstream0
                            local Wdown1
```

真正并行了。

## 到 sg2 时，不再 ARM1 / GET1

当下一轮：

```cpp
specialized_communication(i = sg2)
```

进来时，最前面检查：

```cpp
if (prefetched.valid &&
    prefetched.subgraph == i) {
```

这时 PC sg2 已经完成，因为上一轮已经把它提前计算并置了 `compute_complete=true`。你外层本来就会跳过重复 compute。

于是这里只需要：

```cpp
const ggml_status status =
    backend_ctx->transfer_worker->wait(
        prefetched.task_id);

if (status != GGML_STATUS_SUCCESS) {
    return status;
}
```

然后才把 8KB host 数据落到 PC tmp：

```cpp
ggml_tensor * node_dst =
    backend_ctx->backend_configs[j_dst]
        .cgraphs[i]
        .cgraph_main
        ->nodes[
            backend_ctx
                ->backend_configs[j_dst]
                .cgraphs[i]
                .cgraph_main
                ->n_nodes - 1];

ggml_tensor * node_tmp =
    get_node_aux(node_dst);

set_tmp_data(
    node_tmp,
    j_dst,
    0);

ggml_backend_tensor_set(
    node_tmp,
    prefetched.data.data(),
    0,
    prefetched.data.size());
```

你的 `set_tmp_data()` 当前就是把 aux tensor 放到 PC backend 的 reduction tmp buffer。

然后和现在一样构造：

```cpp
node_red->op     = GGML_OP_ADD;
node_red->src[0] = node_dst;   // PC local Wdown1
node_red->src[1] = node_tmp;   // Phone Wdown1 snapshot
```

执行 ADD1。

最后：

```cpp
prefetched.valid = false;
handled = true;

return GGML_STATUS_SUCCESS;
```

最终这一层就会变成：

```text
PHONE                    NETWORK                 PC

Wdown0 ███████
       snapshot0

Wdown1 █████████
       snapshot1 ─────── GET1 █████████
                   ||          ||
                               downstream0 ███
                               PC Wdown1    ███████

                               ↓
                           host→tmp
                           ADD1 █
```

这比现在又多隐藏了一整段：

```text
snapshot1 + Phone→PC TX1
```

而且安全性没有退步，因为 Phone 上仍然：

```text
GRAPH1
→ SNAPSHOT1
```

严格同 compute socket 排序；PC 网络接收只写 host buffer，不会碰正在计算的 PC backend。

我认为这就是**现在最值得做的下一阶段**。Graph dependency 已经恢复且结果正确后，不要再改 `llama.cpp` 了；下一刀就在 Meta：**one-lookahead snapshot prefetch，拆开“网络接收”和“PC ADD”**。
