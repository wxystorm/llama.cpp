对，这个结果反而把原因基本坐实了：**融合本身没问题，问题是我们第一版把 `GRAPH_RECOMPUTE` 发晚了。**

原来 reuse 分支在 `ggml_backend_rpc_graph_compute()` 里立刻发送 `GRAPH_RECOMPUTE`，所以 Phone Wdown 能和 PC Wdown 并行。 而 `snapshot_arm()` 本来是在后面才发 `SNAPSHOT_TENSOR`。

第一版融合变成了：

```text
原来：

PC Wdown  ────────────────┐
                          │ 并行
Phone Wdown ──────────────┘
       ↑
GRAPH_RECOMPUTE 很早就发

PC compute 完成
      ↓
GET_SNAPSHOT
      ↓
SNAPSHOT_TENSOR


第一版融合：

PC Wdown ──────────────── 完成
                           ↓
GET_SNAPSHOT
                           ↓
GRAPH_RECOMPUTE_SNAPSHOT
                           ↓
                    Phone Wdown
```

这等于为了少一个 RPC，把原来 **PC/Phone Wdown overlap 给破坏了**。

Phone Wdown 本来每层约：

```text
3 ~ 5 ms
```

32 层就是潜在：

```text
96 ~ 160 ms/token
```

而少一个小 RPC 每层省下来的远小于这个，所以略降完全合理。

## 正确的第二版：融合命令仍然在 `graph_compute()` 时立刻发送

关键是要让 `ggml_backend_rpc_graph_compute()` 在开始 Phone Wdown 之前就知道：

```text
snapshot_slot
snapshot_seq
snapshot tensor/output node
```

也就是不能：

```text
graph_compute()
↓
以后 snapshot_arm() 再告诉它
```

而应该：

```text
Meta 先本地 prepare snapshot 信息
↓
graph_compute()
↓
直接发 GRAPH_RECOMPUTE_SNAPSHOT
↓
PC / Phone Wdown 同时开始
```

然后后面的 `snapshot_arm()` **变成 no-op**，因为 Phone 已经知道计算结束后要抓 snapshot。

### 建议加一个纯本地 proc

例如：

```cpp
#define GGML_BACKEND_RPC_PREPARE_GRAPH_SNAPSHOT_PROC \
    "ggml_backend_rpc_prepare_graph_snapshot"
```

它**不发送任何网络数据**，只写 RPC backend context：

```cpp
struct rpc_graph_snapshot_context {
    std::mutex mutex;

    bool active = false;

    const ggml_tensor * tensor = nullptr;

    uint32_t slot = 0;
    uint64_t seq = 0;

    size_t offset = 0;
    size_t size = 0;
};
```

加到：

```cpp
struct ggml_backend_rpc_context {
    ...
    rpc_graph_snapshot_context graph_snapshot;
};
```

本地 prepare：

```cpp
static bool ggml_backend_rpc_prepare_graph_snapshot(
        ggml_backend_t backend,
        const ggml_tensor * tensor,
        size_t offset,
        size_t size,
        uint32_t slot,
        uint64_t seq) {

    auto * ctx =
        static_cast<ggml_backend_rpc_context *>(
            backend->context);

    auto & s = ctx->graph_snapshot;

    std::lock_guard<std::mutex> lock(s.mutex);

    GGML_ASSERT(!s.active);

    s.active = true;
    s.tensor = tensor;
    s.offset = offset;
    s.size   = size;
    s.slot   = slot;
    s.seq    = seq;

    return true;
}
```

注意：**这里只改内存，零 RPC。**

```cpp
set_snapshot_read(true, snapshot_slot, snapshot_seq)
```

把：


这才是融合应该放的位置。

## `ggml_backend_rpc_graph_compute()` reuse 分支消费 prepare 信息

不要再 defer graph。

恢复它原来“立刻发送”的性质。

大概：

```cpp
if (reuse) {
    rpc_graph_snapshot_context prepared {};

    bool use_fused = false;

    {
        auto & s = rpc_ctx->graph_snapshot;

        std::lock_guard<std::mutex> lock(s.mutex);

        if (s.active) {
            prepared.active = true;
            prepared.tensor = s.tensor;
            prepared.slot   = s.slot;
            prepared.seq    = s.seq;
            prepared.offset = s.offset;
            prepared.size   = s.size;

            use_fused = true;
        }
    }

    if (use_fused) {
        const int output_node =
            rpc_find_graph_node(
                cgraph,
                prepared.tensor);

        if (output_node >= 0) {
            rpc_msg_graph_recompute_snapshot_req request {};

            request.device =
                rpc_ctx->device;

            request.graph_uid =
                graph_uid;

            request.slot =
                prepared.slot;

            request.seq =
                prepared.seq;

            request.output_node =
                static_cast<uint32_t>(output_node);

            request.offset =
                prepared.offset;

            request.size =
                prepared.size;

            auto sock =
                get_socket(rpc_ctx->endpoint);

            const bool status =
                send_rpc_cmd_compact_small(
                    sock,
                    RPC_CMD_GRAPH_RECOMPUTE_SNAPSHOT,
                    request);

            RPC_STATUS_ASSERT(status);

            {
                auto & s = rpc_ctx->graph_snapshot;
                std::lock_guard<std::mutex> lock(s.mutex);

                s.active = false;
                s.tensor = nullptr;
            }

            return GGML_STATUS_SUCCESS;
        }
    }

    // fallback：原 GRAPH_RECOMPUTE
    ...
}
```

这里找 node 最好直接按**指针**，不需要名字：

```cpp
static int rpc_find_graph_node(
        const ggml_cgraph * graph,
        const ggml_tensor * target) {

    for (int i = 0; i < graph->n_nodes; ++i) {
        if (graph->nodes[i] == target) {
            return i;
        }
    }

    return -1;
}
```

比：

```text
strncmp("ffn_down_chunk_")
```

还稳。

## 后面的 `snapshot_arm()` 不再真正发送

但不能简单全部 no-op，因为首次：

```text
GRAPH_COMPUTE
```

以及 fallback 路径仍需要旧 `SNAPSHOT_TENSOR`。

所以需要在 backend context 再记录：

```cpp
bool snapshot_was_fused = false;
uint64_t fused_snapshot_seq = 0;
```

当 `graph_compute()` 成功发：

```text
GRAPH_RECOMPUTE_SNAPSHOT
```

时：

```cpp
ctx->snapshot_was_fused = true;
ctx->fused_snapshot_seq = request.seq;
```

然后 `snapshot_arm()`：

```cpp
{
    std::lock_guard<std::mutex> lock(
        rpc_ctx->graph_snapshot.mutex);

    if (rpc_ctx->snapshot_was_fused &&
        rpc_ctx->fused_snapshot_seq == seq) {

        rpc_ctx->snapshot_was_fused = false;

        if (RPC_DEBUG) {
            printf(
                "[RPC_SNAPSHOT_ALREADY_FUSED] "
                "seq=%" PRIu64 "\n",
                seq);
        }

        return true;
    }
}
```

否则继续原来的：

```cpp
RPC_CMD_SNAPSHOT_TENSOR
```

这样：

```text
cache reuse decode Wdown
→ fused

首次 GRAPH_COMPUTE
→ 老 snapshot_arm

其他图
→ 老路径
```

correctness 边界不会被破坏。

### 还有一个更好的小优化

如果改 Meta 的时候方便，甚至可以把：

```text
GET_SNAPSHOT
```

**提前到 `compute_workers.compute(i)` 之前 enqueue**：

```text
prepare snapshot
↓
pre-post GET_SNAPSHOT
↓
启动 PC + Phone compute
```

server 的 `send_snapshot()` 本来就会等待：

```cpp
slot.seq == request.seq &&
slot.state == READY
```

所以提前 GET 是安全的。

最终就是：

```text
transfer socket:
GET_SNAPSHOT ────────────> wait READY

compute socket:
GRAPH_RECOMPUTE_SNAPSHOT -> compute -> READY
                                  │
transfer thread <─────────────────┘
```

这个才是当前架构下非常漂亮的流水。

不过建议**先只做“prepare 提前 + graph_compute 立即 fused”**，GET 的位置先不动。这样变量更少。

你现在这版略降的话，我会把第一版的 **defer graph** 回退，但**保留新 command 和 server `graph_recompute_snapshot()`**，直接改成上面第二版。这样很可能不仅把 `1.1` 找回来，还能再往上走。
